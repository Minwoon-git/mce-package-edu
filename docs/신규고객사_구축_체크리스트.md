# 신규 고객사 MCE 구축 체크리스트

이 저장소는 **신규 고객사 구축 전용 템플릿**. 이전 고객사의 데이터·계정 ID·산출물은 모두 제거된 상태.
계정 고유값은 `<확인필요: …>` 자리표시자로 표시돼 있으며, 구축 과정에서 실제 값으로 채움.

**남은 자리표시자 전체 확인:**

```bash
grep -rn "확인필요" .claude docs README.md
```

---

## 0단계 — (권장) 샘플 데이터로 한 바퀴 돌려보기

실제 고객사 데이터를 붙이기 전에, 동봉된 가상 데이터셋으로 STEP 0→1→2→3을 그대로 체험할 수 있다.
**첫 사용자는 이 단계를 먼저 하는 것을 권장** — 1~5단계에서 무엇이 왜 필요한지가 먼저 이해된다.

| # | 작업 | 참고 |
|---|---|---|
| 1 | 1단계(환경 준비)를 먼저 마친다 | MCP 연결까지 필요 |
| 2 | `docs/schema-samples/urbanmall/` 의 `urbanmall_schema.sql` 첨부 → "스키마 분석해줘" | STEP 0 Phase A/B 체험 |
| 3 | CSV 5종을 GCS에 올리고 Import 실행 | 회원 10,000명 |
| 4 | "어떤 캠페인 만들 수 있어?" → 진단 결과를 샘플 README의 **진단 기대값 표**와 대조 | 값이 맞으면 적재 정상 |
| 5 | 캠페인 1건을 골라 정의서 → 저니(Draft)까지 생성 | 발행하지 않는다 |

> 이메일은 예약 도메인(`example.com`), 휴대폰은 미할당 국번(`010-0000-xxxx`)이라 실제 발송이 외부로 나가지 않는다.
> 그래도 **실습 저니는 Draft로만** 두고, 실습이 끝나면 만들어진 DE·저니를 정리한다.

## 1단계 — 패키지·환경 준비

> 👥 **여러 명이 같은 BU에서 함께 세팅한다면** → [`교육_설치가이드.md`](교육_설치가이드.md) 를 따른다.
> 운영자 1회 작업(패키지 생성·라이선스·접두어 배정)과 개인 PC 작업이 분리돼 있고, 객체 이름 충돌 방지 규칙이 포함돼 있다.

| # | 작업 | 비고 |
|---|---|---|
| 1 | Node.js · Claude Code CLI 설치 | 필수 |
| 2 | 루트에서 `npm install` | `node_modules` 미포함 |
| 3 | `cd web-bridge && npm install` | 챗봇용(express·exceljs) |
| 4 | **Installed Package(Public App) 생성** — Administration → Installed Packages → New → Add Component → API Integration → **Public App** | ⚠️ Server-to-Server 아님. 상세 [README](../README.md) "설치 및 연결 → 1단계" |
| 5 | Client ID(24자)·테넌트 ID(28자) 확인 → Redirect URI를 콜백 URL로 교체 | 엔드포인트 URL 확정 |
| 6 | 그 패키지에서 **사용 계정에 라이선스 부여** | 없으면 7번에서 `user_not_licensed` |
| 7 | `claude mcp add -s user --transport http sf-mce-mcp "<엔드포인트 URL>"` | 4~5번에서 구성한 URL |
| 8 | `claude mcp login sf-mce-mcp` → `/mcp` 로 확인 | 대상 BU로 OAuth 인증 |
| 9 | `web-bridge/config.example.json` → `config.json` 복사 후 `allowedAccounts`에 BU 이름 기입 | 챗봇 버튼 노출 게이트 |
| 10 | (챗봇 사용 시) `web-bridge/autostart-install.cmd` 실행 + Chrome 확장 로드 | [chrome-extension/README](../chrome-extension/README.md) |

> **4~6번은 MC 관리자 권한이 필요합니다.** 교육/실습 계정이라도 이 세 단계를 먼저 밟아야 7번 이후가 동작합니다.
> 엔드포인트 URL을 이미 받았다면 4~5번은 건너뛰고 6번(라이선스)만 확인하면 됩니다.

> **주의** — 사용량은 그 PC의 `claude` CLI 로그인 계정에서 차감. 상세는 [web-bridge/README](../web-bridge/README.md) "사용 계정 · 사용량".

## 2단계 — 고객사 스키마 수집

| # | 작업 | 산출물 |
|---|---|---|
| 1 | `docs/onboarding-kit/MCE_온보딩_가이드템플릿_커머스.xlsx` 고객사 전달 | 작성 요청 |

| 4 | (참고) 같은 스키마의 전량 샘플 — `docs/schema-samples/urbanmall/` | 회수 전 STEP 0 예행연습용 |

## 3단계 — STEP 0 스키마 분석 (`mce-schema-agent`)

| # | 작업 | 결과 |
|---|---|---|
| 1 | 스키마 파일 첨부 후 요청 | Phase A — 표준 매핑표 + 확인 목록 |
| 2 | 핵심 컬럼 확정 (핵심 ID·총구매액 산식·취소환불 제외·동의값 해석) | HITL 승인 |
| 3 | Phase B 실행 | 빈 RAW DE(원본 컬럼명) + GCS Import + Automation(Ready) + `analysis-guide/<고객사>.md` 자동 생성 |
| 4 | 활성 고객사 전환 — `CLAUDE.md`·`mce-campaign/SKILL.md`의 "활성 고객사" 줄 갱신 | 하류 STEP이 새 가이드 참조 |

## 4단계 — 데이터 적재 게이트 ⏳

- 고객사가 **GCS 버킷**에 업로드 → Import 실행 → RAW DE 적재 확인
- **적재 전에는 STEP 1(진단) 불가** — 카운트가 0으로 나옴

## 5단계 — 발송 인프라

| # | 작업 | 스킬 |
|---|---|---|
| 1 | 초기 세팅 점검 (Sender Profile·Send Classification·도메인 인증 등) | `mce-onboarding` |
| 2 | 기본 세팅 3종 — 발송결과 적재 · 감사로그 적재 · IP 워밍 저니 | `mce-base-setup` |
| 3 | 수동 항목 처리 — 도메인 인증(SAP)·전용 IP·물리 주소·구독센터 | 콘솔 작업 (가이드만 제공) |
| 4 | BU 고정값 확정 — Sender Profile·Send Classification·Publication List GUID를 `analysis-guide/<고객사>.md` §7에 기록 | 자리표시자 해소 |

## 6단계 — 캠페인 운영 시작

| # | 작업 | 스킬 |
|---|---|---|
| 1 | 고객 데이터 진단 + 분석 리포트(PPT) 생성 | `mce-campaign` STEP 1 |

| 3 | (알림톡 채널 시) micrm 모바일 컨텐츠 seq 확보 | `reference/micrm-catalog.md` |

## 고객사별로 반드시 교체하는 파일

| 파일 | 내용 | 생성 방법 |
|---|---|---|
| `.claude/skills/mce-campaign/reference/analysis-guide/<고객사>.md` | 컬럼 의미·기획 값·BU 고정값(§7) | STEP 0-B 자동 생성 |
| `CLAUDE.md` · `mce-campaign/SKILL.md` | "활성 고객사" 줄 | 수동 1줄 |

| MCP 엔드포인트 등록 | 테넌트별 URL | `claude mcp add -s user …` → `~/.claude.json`(사용자 전역)에 저장. **저장소에는 파일이 생기지 않는다** — `-s project` 로 등록할 때만 `.mcp.json` 이 만들어진다 |
| `reference/micrm-catalog.md` | 알림톡·카카오 채널 정보 | 고객사 micrm 조회 |
| `reference/email-template/<고객사>.json` | 브랜드 색·로고·푸터 | `_example-brand.json` 복제 |

## 이 템플릿에서 제외된 항목 (원본 대비)

- `.claude/agent-memory/` — 워커 학습 메모리(이전 계정 ID·DE GUID 포함). 운영하면 자동 재생성
- `.claude/journey_history.md` — 헤더만 남긴 빈 파일로 초기화
- `campaign_definitions/*.xlsx` — 이전 고객사 정의서 47건
- `reports/*` — 이전 고객사 분석 리포트(PPTX·PDF·JSON)
- `.claude/_backup_single_agent_*` — 구버전 백업
- `web-bridge/config.json` · `.claude/settings.local.json` — 테넌트·로컬 비밀값
- `docs/requirements_*.md` · 데모 영상 — 패키지 개발 문서
- 특정 고객사 데모 자산(실명 데이터셋·`analysis-guide/<실고객사>.md`) — **실명이 붙은 자료는 템플릿에 두지 않는다.** 실습이 필요하면 위 `urbanmall` 중립 데이터셋을 쓴다
