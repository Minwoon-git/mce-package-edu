# 교육용 설치 가이드 — MCE 캠페인 자동화

**전제**: 교육생 전원이 **같은 MC 조직(테넌트)** 안에서 **각자의 사용자 계정**과 **각자의 PC**를 사용한다.
→ 엔드포인트 URL은 **전원 동일**하고, Installed Package는 **운영자가 1회만** 만든다.

> 화면 단위 상세·전체 오류 사전은 [`README.md`](../README.md)("다른 PC에서 가져와 사용하기", "설치 및 연결")가 원본이다.
> 이 문서는 그것을 **교육 진행 순서로 재구성**하고, 교육에서만 필요한 항목(접두어 배정·실습 격리)을 더한 것이다.

---

## 0. 전체 그림 — 누가 무엇을

| 구분 | 작업 | 횟수 | 권한 |
|---|---|---|---|
| **운영자** | Installed Package(Public App) 생성 → 엔드포인트 URL 확정 | 전체 1회 | MC 관리자 |
| **운영자** | 교육생 전원에게 패키지 **라이선스 부여** | 인원수 | MC 관리자 |
| **운영자** | URL·접두어·레포 링크 배포 | 1회 | — |
| **교육생** | Node.js + Claude Code 설치 | PC당 1회 | — |
| **교육생** | 레포 clone + `npm install` | 1회 | — |
| **교육생** | `claude mcp add` + `claude mcp login` | 1회 | 본인 MC 계정 |

> ⚠️ **운영자 작업이 끝나기 전엔 교육생이 3단계에서 막힙니다.** 교육 최소 3일 전에 Part 1을 마치세요.
> 단, 교육생의 1~2단계(설치·clone)는 URL 없이도 가능하므로 **미리 해 오게 하면** 교육 당일 시간을 크게 아낍니다.

# Part 1 — 운영자 사전 준비 (교육 전, 1회)

## 1-1. 대상 BU 확정

교육생이 실습할 **Business Unit 하나**를 정한다. 여기에 실습 DE·저니가 전부 쌓인다.

> 교육생별로 BU를 나눠 줄 수 있으면 가장 안전하다. 어려우면 1-5의 **접두어**로 분리한다.

## 1-2. Installed Package (Public App) 생성

Administration → **Installed Packages** → **New** → 이름 입력 → **Add Component** → **API Integration**

| # | 작업 | 비고 |
|---|---|---|
| 1 | Integration 유형 **Public App** 선택 | ⚠️ **Server-to-Server 아님** |
| 2 | Redirect URI에 임시값 `https://salesforce.com` 입력 | 4번에서 교체 |
| 3 | 권한(Scope) 체크 후 저장 | 아래 표 |
| 4 | **Client ID(24자)** · **테넌트 ID(28자)** 확인 → Redirect URI를 실제 콜백 URL로 교체 | 1-3 참조 |

**권한(Scope)**

| 카테고리 | 권한 |
|---|---|
| Email | Read, Write, Send |
| Journeys | Read, Write, Execute |
| List and Subscribers | Read, Write |
| Data Extensions | Read, Write |
| Contacts | Read, Write |
| Automation | Read, Write, Execute |
| SMS | Read, Write, Send |
| Push | Read, Write, Send |

> ⚠️ **`Server-to-Server` 로 만들면 안 된다.** 그쪽은 `client_credentials`(서버가 인증) 방식이라 사용자 OAuth 로그인을 못 받는다.
> **패키지 타입은 생성 후 변경할 수 없어** 잘못 만들면 처음부터 다시 만들어야 한다.
> `Client Secret` 은 쓰지 않는다 — Public App은 사용자가 브라우저로 로그인한다.

## 1-3. 엔드포인트 URL 구성

1-2에서 얻은 두 값으로 조립한다. **이 URL 한 줄이 교육생 전원에게 배포할 값**이다.

```
https://mai-mce-mcp-cdp1.sfdc-yfeipo.svc.sfdcfc.net/t/<테넌트ID>/c/<클라이언트ID>/api/mcp
```

- `<테넌트ID>` — Authentication Base URI `https://<28자>.auth.marketingcloudapis.com` 의 28자
- `<클라이언트ID>` — 패키지 상세 → API Integration 컴포넌트의 24자
- US 스택 기준. EU 스택이면 `sfdc-yfeipo` → `sfdc-yzvdd4`

**Redirect URI 교체값** (1-2의 4번):

```
https://mai-mce-mcp-cdp1.sfdc-yfeipo.svc.sfdcfc.net/t/<테넌트ID>/c/<클라이언트ID>/api/mcp/oauth/callback
```

> Redirect URI에 Client ID가 들어가는데 Client ID는 저장해야 나온다. 그래서 임시값 → 저장 → 교체 순서가 된다. 정상이다.

## 1-4. 교육생 라이선스 부여 ⭐

Administration → Installed Packages → **해당 패키지** → 교육생 계정에 라이선스 부여.

> **패키지 생성과 별개 작업이다.** 빠뜨리면 교육생은 `claude mcp add` 까지 멀쩡히 되고 `claude mcp login` 에서
> `user_not_licensed` 로 막힌다. 오류 메시지가 원인을 짚어주지 않아 교육 중 가장 많이 시간을 잡아먹는 지점이다.
>
> **교육 전에 운영자가 직접 1명분을 끝까지 인증해 보고** 넘어가라. 되면 나머지도 된다.

## 1-5. 교육생 접두어 + 데이터셋 배정 ⭐

한 BU를 공유하면 **두 군데에서 충돌한다.** 둘 다 막아야 한다.

**① 객체 이름 충돌** — 교육생이 각자 STEP 0~1을 돌리면 `RECON_Profile`·`SEG_*`·진입 DE를
**같은 이름으로** 만들어 서로 덮어쓴다. → **접두어**로 분리한다.

> 가정이 아니라 이미 겪은 사고다 — [`error-log.md`](../.claude/skills/mce-campaign/reference/error-log.md) "고객사 간 DE 이름 충돌" 항목.

**② Contact Key 충돌** — DE 이름을 갈라도 **All Contacts / All Subscribers 는 BU 공용**이다.
두 사람의 회원ID·이메일·휴대폰이 같으면 **같은 사람으로 합쳐진다.** → **데이터셋**을 분리한다.
동봉 데이터셋은 이 목적에 맞게 ID 대역이 처음부터 어긋나 있다.

| 교육생 | 접두어 | 실습 데이터셋 | 회원ID 대역 | 이메일 | 휴대폰 |
|---|---|---|---|---|---|
| 1번 | `EDU01` | [`test_data/EDU01/`](../test_data/EDU01/) | 1020001 ~ 1023000 | `e1-00001@example.com` | 010-0000-3001 ~ 6000 |
| 2번 | `EDU02` | [`test_data/EDU02/`](../test_data/EDU02/) | 2020001 ~ 2023000 | `e2-00001@example.com` | 010-0000-6001 ~ 9000 |

- **스키마(DDL)는 두 벌이 완전히 동일**하다 — 같은 화면을 보며 같은 속도로 진행할 수 있다.
  [`urbanmall_schema.sql`](schema-samples/urbanmall/urbanmall_schema.sql) 하나를 둘 다 STEP 0 입력으로 쓴다.
- **데이터 값(시드)은 다르다** — 진단 비율이 서로 달라서, 내 결과가 남의 DE에서 나온 건지 바로 구분된다.
  각 폴더의 `진단기대값.md` 가 그 교육생 전용 **정답지**다.
- 3명 이상이면 프로필을 늘린다 — [`generate_urbanmall_dataset.js`](schema-samples/urbanmall/generate_urbanmall_dataset.js) 상단 `PROFILES` 에
  `EDU03: { seed, idbase: 3020000, mailtag: 'e3-', hpbase: 9000, out: '../../../test_data/EDU03' }` 을 추가하고 `--profile=EDU03` 으로 생성.
  (⚠️ `hpbase + 3000 ≤ 9999` 를 넘기면 휴대폰 대역이 미할당 국번을 벗어난다 — 그때는 회원 수를 줄이거나 번호 규칙을 바꾼다.)

> 접두어는 **DE·저니·Automation·Query·이메일 에셋·Event Definition 전부**에 붙는다. 데이터셋은 **적재되는 값**을 가른다.
> 둘 중 하나만 해서는 격리가 안 된다.

# Part 2 — 교육생 PC 세팅 (각자)

소요 30~40분. **1~2단계는 URL 없이도 가능**하므로 교육 전에 미리 해 두면 좋다.

## 1단계 — Node.js + Claude Code 설치 (PC당 1회)

**① Node.js LTS** — [nodejs.org](https://nodejs.org)

```bash
node -v
```

**② Claude Code** — 둘 중 하나

```powershell
irm https://claude.ai/install.ps1 | iex
```

```bash
npm install -g @anthropic-ai/claude-code
```

설치 후 **터미널을 완전히 닫고 새로 연 다음** 확인:

```bash
claude --version
```

**③ Anthropic 계정 로그인** — `claude` 실행 시 브라우저로 1회

> 💡 PowerShell 네이티브 설치(방법 1)는 Node 없이도 Claude Code가 깔리지만, **Node.js는 어차피 필요하다.**
> 이 패키지의 xlsx 정의서·PPT 리포트 생성이 Node로 돌아간다.

## 2단계 — 프로젝트 준비

```bash
git clone https://github.com/Minwoon-git/mce-package-edu.git
cd mce-package-edu
npm install
```

> ⚠️ **OneDrive·바탕화면 동기화 폴더는 피한다.** 파일 잠금으로 `npm install` 이 `EPERM` 으로 실패한다.
> `C:\work\` 같은 동기화 밖 경로를 권장한다.
> clone 위치·폴더명은 자유다 — Claude Code가 실행 시 현재 폴더를 프로젝트 루트로 잡는다.

## 3단계 — MCP 연결

운영자에게 받은 URL로 등록한다.

```bash
claude mcp add -s user --transport http sf-mce-mcp "<운영자가 준 엔드포인트 URL>"
```

| 옵션 | 뜻 |
|---|---|
| `-s user` | PC 전체에 등록 — 폴더를 옮기거나 복사본을 만들어도 재등록 불필요 |
| `--transport http` | **필수.** 빠뜨리면 로컬(stdio) 서버로 잡혀 연결되지 않는다 |
| `sf-mce-mcp` | **이름 고정.** 바꾸면 OAuth 재인증이 필요하고 스킬이 못 찾는다 |

이어서 본인 MC 계정으로 인증한다.

```bash
claude mcp login sf-mce-mcp
```

## 4단계 — 동작 확인 ⭐

**반드시 clone한 폴더 안에서** 실행한다.

```bash
cd mce-package-edu
claude
```

| # | 확인 | 정상 |
|---|---|---|
| 1 | `/mcp` 입력 | `Authentication successful. Connected to sf-mce-mcp.` |
| 2 | "저니 목록 보여줘" | 실시간 조회 결과가 표로 나옴 |
| 3 | "어떤 캠페인 만들 수 있어?" | **"활성 고객사가 없으니 STEP 0(스키마 분석)부터 하자"** 는 안내가 나옴 |

> ⚠️ **3번이 가장 중요하다.** 1~2번은 MCP만 붙어도 되지만, 3번은 `CLAUDE.md`·`.claude/skills`·`.claude/agents`
> 가 로드돼야 동작한다. 이건 **프로젝트 스코프**라 **clone 폴더 안에서 실행해야만** 붙는다.
> 폴더 밖에서 실행하면 "연결은 됐는데 캠페인은 안 만들어짐" 상태가 되고 원인을 찾기 어렵다.
>
> 📌 **아직 데이터를 안 올렸으니 추천 목록이 나오면 오히려 이상하다.** 배포본은 활성 고객사가 `null`
> ([`active-customer.json`](../.claude/skills/mce-campaign/reference/active-customer.json))로 비워져 있어,
> "STEP 0부터" 라는 답이 나오는 게 정상이다. 이 답이 나왔다는 것 자체가 스킬이 로드됐다는 증거다.
> 반대로 **남의 진단 결과가 그냥 나온다면** 다른 교육생 DE를 읽고 있다는 신호다 — Part 4를 본다.

# Part 3 — 실습 시작 전 규칙

## ① 접두어를 반드시 쓴다

배정받은 접두어를 **첫 요청에 명시**한다.

```
내 접두어는 EDU01이야. 고객사명도 EDU01로 잡고, 만드는 DE·저니·Automation·Query·
이메일·Event Definition 이름 앞에 전부 EDU01_ 을 붙여줘.
실습 데이터는 test_data/EDU01/ 을 쓴다.
```

**"고객사명도 EDU01" 이 핵심이다.** 패키지는 생성 객체 이름을 `<접두어>_…` 로 짓는데 그 접두어의
기본값이 고객사명이다. 여기서 "어반몰"이라고 하면 두 사람 다 `URBANMALL_RECON_Profile` 을 만들어
**서로 덮어쓴다.** 접두어를 고객사명으로 선언하면 STEP 0이 만드는 가이드(`analysis-guide/EDU01.md`)에
`EDU01_…` 이름이 기록되고, STEP 1~4가 전부 그 이름을 따라간다.

접두어 없이 STEP 0~1을 돌리면 다른 교육생의 DE를 덮어쓴다.

> 💡 **매 세션 말하기 싫으면** clone 폴더의 `CLAUDE.md` 맨 위에 같은 문장을 한 줄 적어 둔다.
> 프로젝트 파일이라 세션마다 자동으로 읽힌다. (Claude의 기억은 PC·폴더마다 따로라 레포에 안 딸려온다.)

## ①-2 내 데이터셋만 올린다

배정받은 폴더의 CSV 5종만 SFMC UI로 업로드한다 — `test_data/EDU01/` 또는 `test_data/EDU02/`.
두 폴더는 **회원ID·이메일·휴대폰 대역이 서로 어긋나 있어** 같은 BU에 올려도 All Contacts 에서 섞이지 않는다.
남의 폴더 CSV를 올리면 그 격리가 깨진다.

STEP 0 입력으로 쓰는 DDL은 **두 사람 공통**이다 — [`schema-samples/urbanmall/urbanmall_schema.sql`](schema-samples/urbanmall/urbanmall_schema.sql).

## ② 저니는 Draft로만 둔다

이 패키지는 기본이 Draft 생성이다. **발행(publish)하지 않는다.**
실습 데이터셋(`test_data/EDU01`·`test_data/EDU02`)은 이메일이 예약 도메인(`example.com`),
휴대폰이 미할당 국번(`010-0000-xxxx`)이라 실제로는 도달하지 않지만, 습관을 들이는 게 목적이다.

## ③ git push 하지 않는다

STEP 0을 돌리면 **git이 추적하는 파일이 바뀐다** — `active-customer.json`(활성 고객사 전환)과
새로 생기는 `analysis-guide/<고객사>.md`. 두 사람이 각자 다른 값으로 바꾸므로 push 하면 바로 충돌한다.

```
실습 중에는 commit·push 하지 않는다. (pull 도 하지 않는다)
```

충돌을 이미 만들었다면 `git checkout -- .` 로 되돌리지 말 것 — 자기 STEP 0 결과가 날아간다.
운영자를 부르거나, 각자 브랜치를 파고 거기서만 작업한다.

## ④ 기본 세팅(발송결과·감사로그)은 BU 공용이다

`mce-base-setup`("기본세팅")이 읽는 데이터뷰(`_Sent`/`_Open` 등)와 감사로그는 **BU 단위**라,
두 사람이 각자 돌려도 **같은 데이터**가 들어간다. 접두어로 객체 이름만 갈릴 뿐 내용은 동일하고
일배치 Automation만 두 벌 생긴다. **한 명이 시연하고 다른 한 명은 결과를 같이 보는 편**이 낫다.

## ⑤ 실습이 끝나면 정리한다

본인 접두어로 검색해 아래를 **전부** 지운다. 하나라도 남으면 다음 실습에서 이름 충돌이 난다.

| 대상 | 위치 |
|---|---|
| RAW DE 5종 · `RECON_Profile` · `SEG_*` · 진입 DE | Data Extensions |
| SQL Query · Automation | Automation Studio |
| 이메일 에셋 | Content Builder |
| **Event Definition** | Journey Builder — ⚠️ 남아 있으면 **같은 이름으로 재생성이 아예 실패**한다 |
| Journey (Draft) | Journey Builder |

Contact 삭제는 느리다(3,000명 × 2인). 컨택트까지 지울 거면 실습 직후에 걸어 두고 기다린다.

## ⑥ 실습 코스

[`신규고객사_구축_체크리스트.md`](신규고객사_구축_체크리스트.md) **0단계**를 따라간다.
**본인 데이터셋**으로 STEP 0 → 1 → 2 → 3을 한 바퀴 도는 코스이며,
`test_data/EDU01/진단기대값.md`(또는 `EDU02`)의 **진단 기대값 표**와 대조해 제대로 따라왔는지 스스로 확인한다.
두 사람의 기대값은 서로 다르다 — **옆 사람과 값이 똑같이 나오면 남의 DE를 읽고 있는 것**이다.

## 교육에서 특히 자주 나오는 것들

| 증상 | 원인 | 해결 |
|---|---|---|
| `claude mcp login` 에서 **`user_not_licensed`** | 운영자가 그 계정에 **패키지 라이선스를 안 줬다** (Claude Code 문제 아님) | 운영자에게 요청. 이미 부여됐다는데도 나면, **라이선스가 정상 동작하는 사용자가 먼저 재인증**한 뒤 다시 시도 |
| MCP는 붙었는데 **"캠페인 만들어줘"가 안 먹음** | clone 폴더 **밖에서** `claude` 실행 | `cd <clone 폴더>` 후 다시 실행 |
| 내가 만든 DE가 **사라지거나 값이 바뀜** | 다른 교육생과 **이름 충돌** | Part 3 ① 접두어 적용 후 재생성 |
| **옆 사람과 진단값이 똑같이 나옴** | 남의 분석 DE를 읽고 있다 (접두어 누락 / 활성 고객사가 남의 것으로 잡힘) | `active-customer.json` 의 `analysis_guide` 가 **내 고객사 파일**을 가리키는지 확인 → 아니면 접두어를 말하고 STEP 0부터 다시 |
| 데이터를 올리기도 전에 **추천 캠페인이 나옴** | 계정에 남아 있는 **다른 사람의 DE**를 읽었다 | 정상이 아니다. STEP 0부터 본인 접두어로 다시 |
| Event Definition 생성이 **이름 중복으로 실패** | 이전 실습 잔여물이 안 지워졌다 | Journey Builder 에서 접두어로 검색해 삭제 후 재시도 |
| `git pull`/`push` 가 **충돌** | STEP 0이 `active-customer.json`·가이드 MD를 고친다 | Part 3 ③ — 실습 중엔 commit/push/pull 하지 않는다 |
